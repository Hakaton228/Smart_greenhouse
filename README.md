# 🌿 Умная оранжерея

**Одностраничная система мониторинга и управления коллекцией редких растений**

## 📖 О проекте

**«Умная оранжерея»** — демонстрационный интерфейс системы мониторинга ботанической
оранжереи, ориентированный на коллекцию охраняемых видов (флора Красной книги:
луковые, ирисовые, злаки, орхидные и др.). Приложение показывает, как оператор
(руководитель) и наблюдатель (ученик) видят состояние зон, управляют климатом,
ведут план посадок, загружают фотографии растений, отслеживают тревоги и экономику
содержания.

Проект выполнен как **единый самодостаточный HTML‑файл** без сборки, бэкенда и
npm‑зависимостей: его можно открыть двойным кликом, положить на любой статический
хостинг (GitHub Pages, Netlify, Vercel) или пересылать коллеге — вместе со всеми
данными и фотографиями.

> ⚠️ Это **прототип / учебная демонстрация**. Значения климата задаются вручную
> ползунками и симулируются, интеграция с реальными датчиками и серверная
> авторизация — в дорожной карте (см. ниже). Пароли в интерфейсе служат для
> разграничения ролей в демо, а не для безопасности.

## ✨ Ключевые возможности

- 🗺️ **Интерактивная схема оранжереи** — 7 зон + лаборантная, два яруса
  (верхний / нижний), переключаемых одним кликом.
- 🎥 **Обзорная «камера» на всю оранжерею** — открывается по клику на коридор,
  показывает все зоны и их статусы в одном экране.
- 🌡️ **Климат‑контроль по зонам** — 7 метрик (температура воздуха и субстрата,
  влажность воздуха и субстрата, pH, освещённость, EC) с ползунками, черновиком
  изменений и сохранением в журнал.
- 🪴 **План посадок** — виды по ярусам, количество особей, +/- особи, удаление вида,
  добавление нового вида с фото и характеристиками.
- 🌱 **Карточка растения** — описание, допустимые параметры вида, ежедневные фото,
  оценка необходимости проверки специалистом (вердикт + приоритет), история роста,
  история условий и история проверок.
- 🖼️ **Фотографии растений** — загрузка из файла **или вставка через `Ctrl + V`**,
  автоматическое сжатие, замена эмодзи‑заглушки на реальное фото.
- 📰 **Журнал событий** с фильтрами (климат / полив / химия / обслуживание / тревоги).
- 🔔 **Уведомления надзора** с приоритетом (критично / внимание / инфо) и отметкой
  «прочитано».
- 📊 **Статистика** — экономика (₽/мес по категориям), полив, количество видов,
  прирост и цветение, сводные климатические графики за 24 ч (рисуются на `<canvas>`,
  без библиотек).
- 💾 **Сохранение «в файл»** — настройки, журнал, статистика и **фото в base64**
  записываются внутрь самого HTML через `File System Access API` (или скачиванием
  копии), а при следующем открытии подхватываются автоматически.
- 🔐 **Две роли** — Ученик (только просмотр) и Руководитель (полный доступ).
- 🌙 Тёмная тема, адаптивная вёрстка, логотип‑лист в SVG, favicon.

## 🚀 Быстрый старт

Приложению **не нужны** установка, сборка и интернет (кроме подгрузки шрифтов Google
Fonts; без сети оно работает со системными фолбэками).

### Вариант 1 — локально

1. Скачайте / склонируйте репозиторий.
2. Откройте `index.html` (или `smart_greenhouse.html`) двойным кликом в браузере.
3. Войдите в системе (пароли ниже).

### Вариант 2 — GitHub Pages

1. Запушьте файл в репозиторий (например, как `index.html` в `main` или в `/docs`).
2. **Settings → Pages** → выберите источник → Save.
3. Откройте опубликованный URL.

### Вариант 3 — любой статический хостинг

Перетащите HTML‑файл в Netlify Drop / Vercel / Cloudflare Pages — готово.

### Коридор и обзорная камера

Коридор идёт во всю ширину между рядами зон. Клик по нему открывает поверх схемы
модальное окно **«Обзорная камера»** — сетку всех зон + лаборантной с их текущими
статусами и анимированными иконками (заглушка видеопотока). Закрытие — `Esc` или
клик вне окна.

## 🌡️ Мониторинг параметров

Каждая зона измеряется по 7 метрикам:

| Ключ | Название | Единица | Диапазон контроллера |
|---|---|---|---|
| `airTemp` | Температура воздуха | °C | 5…45 |
| `soilTemp` | Температура субстрата | °C | 3…40 |
| `airHum` | Влажность воздуха | % | 10…99 |
| `soilHum` | Влажность субстрата | % | 5…99 |
| `ph` | Кислотность | pH | 3…9 |
| `light` | Освещённость | % | 0…100 |
| `ec` | Электропроводность | мСм/см | 0…4 |

**Как считается статус.** У каждого вида своё *допустимое окно* по каждой метрике
(редактируется руководителем в карточке вида). Статус параметра растения:
`ok` (в окне) → `warn` (выход в пределах порога тревоги) → `bad` (сильный выход).
Статус зоны = худший статус среди её растений (а если растений на ярусе нет —
сравнение с профилем типа зоны). Отсюда бейджи **НОРМА / ВНИМАНИЕ / ТРЕВОГА** и
уведомления надзора.

## 🌱 Карточка растения

При выборе особи на плане посадки справа открывается полная характеристика:

1. **Ежедневные фотографии** — лента снимков роста (фото вида или анимированная
   заглушка‑росток), клик — просмотр в лайтбоксе.
2. **Оценка необходимости проверки** — вердикт (*не требуется / рекомендована /
   срочная*), процентный приоритет и текстовое обоснование по отклонениям.
3. **История роста** — график высоты на `<canvas>` + хронология стадий
   (посадка → прорастание → листья → бутонизация → цветение).
4. **История условий содержания** — изменения метрик зоны с источником
   (авто‑система / оператор).
5. **История проверок специалистом** — визиты агронома/инспектора с вердиктами.

## 📰 Журнал и 🔔 уведомления

- **Журнал событий** фиксирует климат, полив, химию среды, обслуживание и тревоги;
  фильтруется по категориям, обновляется в реальном времени, хранит до 300 записей.
- **Уведомления надзора** генерируются автоматически при появлении `warn`/`bad`
  в зоне, имеют приоритет (`critical` / `warning` / `info`) и могут быть помечены
  прочитанными (не удаляются, а «серятся»). Счётчик непрожитых тревог — на вкладке
  в сайдбаре.

## 📊 Статистика

Вкладка «Статистика» содержит KPI и блоки (часть редактируется руководителем):

- **Экономика** — таблица ₽/мес по категориям (электроэнергия, вода, удобрения,
  лампы/фильтры, отопление/охлаждение) + стековая диаграмма с линией итога.
- **Сводные климатические графики** — 5 мини‑графиков за 24 ч (t воздуха, влажн.
  воздуха, t субстрата, влажн. субстрата, PPFD), строятся по истории изменений.
- **Полив** — объём л/сут, л/растение, частота циклов + столбчатый график.
- **Виды** — количество растений по видам (горизонтальные бары).
- **Прирост и цветение** — таблицы/бары по видам (см, листья, побеги, дни цветения).

Все графики нарисованы вручную на Canvas API — без чарт‑библиотек.

## 🖼️ Работа с фотографиями

- Загрузка через кнопку **«Загрузить фото»** в форме вида или **вставка из буфера
  `Ctrl + V`** (когда фокус в поле фото / открыта форма редактирования).
- Изображение автоматически сжимается до ~1600 px по большей стороне и кодируется
  в JPEG‑base64, чтобы не раздувать файл чрезмерно.
- Фото привязано к **виду** (имени) и отображается в плане посадки, карточке,
  ленте дней, статистике и лайтбоксе. Эмодзи остаётся фолбэком, если фото нет.

## 💾 Как хранятся данные (главная фишка)

Приложение использует **три уровня хранения**, поэтому ваши фото и настройки
переживают перезагрузку, перенос на другой ПК и пересылку файла:

```
        действие пользователя
                 │
                 ▼
   ┌──────────────────────────┐
   │ 1) localStorage           │  мгновенно, в этом браузере/профиле
   │    key: smart_greenhouse_v10
   └──────────────────────────┘
                 │  кнопка «💾 В файл» / авто-сохранение
                 ▼
   ┌──────────────────────────┐
   │ 2) embeddedState (JSON)   │  внутри самого HTML:
   │    <script id="...">      │  v, updatedAt, зоны, растения,
   │                           │  журнал, фото(base64), статистика…
   └──────────────────────────┘
                 │  открытие файла
                 ▼
   ┌──────────────────────────┐
   │ 3) выбор источника        │  при старте сравнивается updatedAt
   │    embedded vs local      │  встроенного и localStorage — берётся
   │                           │  более свежее; «📂 Из файла» принудительно
   └──────────────────────────┘  грузит состояние из выбранного HTML/JSON
```

- **«💾 В файл»** — в Chromium записывает актуальное состояние (включая фото)
  обратно в открытый HTML‑файл через `File System Access API`; после первого
  выбора файла дальнейшие изменения пишутся туда **автоматически** (с дебаунсом).
  В Firefox/Safari скачивает новую копию `smart_greenhouse_<дата>.html`.
- **«📂 Из файла»** — принудительно загружает состояние из выбранного HTML или
  чистого JSON (полезно, чтобы восстановить данные из присланной копии).
- **`updatedAt`** гарантирует, что при конфликте «файл vs браузер» побеждают более
  свежие данные, а не теряются.

> 📦 Фото в base64 увеличивают размер HTML. Десятки снимков — это мегабайты: это
> нормально для одиночного файла, но при большом архиве рассмотрите вынос фото на
> бэкенд/CDN (дорожная карта).

##  Технологии

| Слой | Что использовано | Почему |
|---|---|---|
| Разметка | семантический HTML5 | один файл, без фреймворка |
| Стили | CSS Custom Properties, Grid, Flexbox, media‑queries | тёмная тема, адаптивность |
| Логика | Vanilla JavaScript (ES2020+) | no‑build, открывается везде |
| Графики | Canvas 2D API (кривые Безье, столбцы, стеки) | ноль зависимостей |
| Изображения | Canvas → `toDataURL` (сжатие JPEG) | фото живут внутри файла |
| Персистентность | `localStorage` + `File System Access API` + встроенный JSON | офлайн + запись «в файл» |
| Шрифты | Space Grotesk + JetBrains Mono (Google Fonts) | фирменный вид; есть фолбэк |
| Иконки/лого | эмодзи + инлайн‑SVG (лист) | без внешних ассетов |

Явно **без** React/Vue, сборщиков, npm и бэкенда — осознанный выбор для
портативного учебного демо.

## ⚠️ Известные ограничения и примечания

- **Нет реальных датчиков.** Климат задаётся руководителем и симулируется;
  интеграция с железом (MQTT/Modbus/REST) — следующий шаг.
- **Клиентские пароли.** Роли — это UX‑демо, а не безопасность.
- **Запись «в тот же файл»** доступна только в браузерах на Chromium
  (File System Access API); остальные получают скачанную копию.
- **Размер файла растёт с числом фото** (base64). Сжатие смягчает, но не решает
  полностью.
- **Эмодзи зависят от ОС/шрифта.** Поэтому спорные глифы заменены на совместимые,
  а там, где важно, используются фото и инлайн‑SVG.
- **Нет синхронизации между устройствами** «из коробки»: перенос — через файл
  («В файл» → «Из файла») или общий хостинг.
- Данные климатической истории и журнала ограничены (последние сутки / 300 записей /
  200 уведомлений), чтобы файл не рос бесконечно.
